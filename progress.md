🌐 День 1 — Что такое HTML и как устроена веб-страница

Сегодня начинаем действительно с нуля. Никаких предположений, что ты уже что-то помнишь.

Наша цель на сегодня — понять, что такое HTML, из чего состоит HTML-документ и как браузер вообще воспринимает написанный нами код.

1. Что такое HTML?

Начнём с самого главного.

HTML — это язык разметки, который используется для создания структуры веб-страницы.

Расшифровывается:

HTML — HyperText Markup Language

То есть язык гипертекстовой разметки.

Обрати внимание на слово «разметки».

HTML сам по себе не предназначен для того, чтобы делать страницу красивой.

Например, HTML может сказать:

«Вот здесь находится заголовок».

«Вот здесь находится абзац».

«Вот здесь находится изображение».

«Вот здесь находится ссылка».

А уже CSS будет отвечать примерно за:

«Сделай заголовок синим, большим и размести его по центру».

А JavaScript — например:

«Когда пользователь нажмёт эту кнопку, выполни какое-нибудь действие».

Условно:

HTML
 ↓
СТРУКТУРА

CSS
 ↓
ВНЕШНИЙ ВИД

JavaScript
 ↓
ПОВЕДЕНИЕ

Представь дом:

HTML       → стены, комнаты, двери
CSS        → цвет стен, мебель, оформление
JavaScript → электричество, автоматические двери и т.д.

Это упрощённая аналогия, но для начала она хорошо подходит.

2. HTML не является языком программирования

Это тоже важно сразу зафиксировать.

HTML — не язык программирования.

Почему?

Потому что в HTML нет привычной нам логики вроде:

если...
иначе...
повтори...
вычисли...

HTML описывает структуру и содержание документа.

Например:

<h1>Мой сайт</h1>
<p>Привет, мир!</p>

Мы не говорим компьютеру:

«Выполни функцию h1».

Мы говорим:

«Этот текст является заголовком первого уровня».

И:

«Этот текст является абзацем».

3. Что такое HTML-тег?

Вот это:

<h1>

— тег.

А вот это:

</h1>

— закрывающий тег.

Разница заключается в /.

Например:

<h1>Привет!</h1>

Здесь:

<h1>
 ↓
открывающий тег

Привет!
 ↓
содержимое

</h1>
 ↓
закрывающий тег

Вместе они образуют HTML-элемент.

То есть:

<h1>Привет!</h1>
└───────────────┘
   HTML-элемент

Это различие важно:

тег — <h1>

элемент — <h1>Привет!</h1>

4. Первый HTML-элемент

Напишем:

<h1>Привет!</h1>

Браузер увидит это и поймёт:

«Ага, это заголовок первого уровня».

На странице пользователь увидит примерно:

Привет!

При этом браузер не показывает сами <h1> и </h1>.

Они нужны браузеру для понимания структуры.

5. Заголовки

В HTML существует несколько уровней заголовков:

<h1>Заголовок 1</h1>
<h2>Заголовок 2</h2>
<h3>Заголовок 3</h3>
<h4>Заголовок 4</h4>
<h5>Заголовок 5</h5>
<h6>Заголовок 6</h6>

От h1 до h6.

Условно:

h1 → самый важный уровень
h2 → подзаголовок
h3 → подзаголовок внутри h2
...
h6 → самый низкий уровень

Важно: это не просто «размер текста».

h1 означает именно заголовок первого уровня.

То, что браузер по умолчанию делает его большим, — уже вопрос стандартных стилей.

Позже CSS позволит нам сделать:

<h1>Привет</h1>

хоть маленьким:

h1 {
    font-size: 14px;
}

Поэтому HTML отвечает за смысл и структуру, а CSS — за оформление.

6. Абзацы

Для обычного текста используется:

<p>Это мой первый абзац.</p>

p — paragraph, то есть абзац.

Можно написать несколько:

<p>Первый абзац.</p>

<p>Второй абзац.</p>

<p>Третий абзац.</p>

Браузер поймёт, что это три отдельных абзаца.

7. А что будет, если написать просто текст?

Например:

Привет!
Как дела?
Я изучаю HTML.

Браузер всё равно сможет это показать.

Но мы пока не сказали ему, какую роль играет этот текст.

Гораздо правильнее написать:

<h1>Привет!</h1>

<p>Как дела?</p>

<p>Я изучаю HTML.</p>

Теперь структура понятна:

Страница
│
├── Заголовок
│
├── Абзац
│
└── Абзац

И именно создание такой структуры — одна из главных задач HTML.

8. А теперь — полноценный HTML-документ

До этого мы писали отдельные элементы.

Но обычно HTML-страница имеет определённую структуру:

<!DOCTYPE html>

<html>
    <head>
        
    </head>

    <body>
        
    </body>
</html>

Не пугайся. Сейчас разберём каждую часть.

9. <!DOCTYPE html>

Первая строка:

<!DOCTYPE html>

говорит браузеру:

«Этот документ использует современный стандарт HTML».

Это называется DOCTYPE.

Для начала достаточно запомнить:

<!DOCTYPE html>

ставится в самом начале HTML-документа.

10. <html>

Дальше:

<html>
    
</html>

Это корневой элемент документа.

То есть практически весь HTML нашей страницы находится внутри него:

<html>

    здесь будет наша страница

</html>

Можно представить:

html
│
├── head
│
└── body
11. <head>

Внутри <html> находится:

<head>
    
</head>

head содержит служебную информацию о странице.

Например:

название страницы;
настройки кодировки;
подключение CSS;
различные метаданные.

Важный момент:

содержимое <head> обычно не является непосредственно содержимым страницы, которое пользователь видит.

Например:

<head>
    <title>Мой сайт</title>
</head>

title задаёт название страницы, которое браузер использует, например, во вкладке.

12. <body>

А вот:

<body>
    
</body>

— это уже основное содержимое страницы.

Именно сюда мы будем помещать:

заголовки;
текст;
изображения;
ссылки;
кнопки;
формы;
списки;
различные блоки и многое другое.

Например:

<body>
    <h1>Мой сайт</h1>

    <p>Добро пожаловать!</p>
</body>

Получается:

html
│
├── head
│
│   └── служебная информация
│
└── body
    │
    ├── h1
    │
    └── p
13. Собираем всё вместе

Получаем:

<!DOCTYPE html>
<html>
    <head>
        <title>Моя первая страница</title>
    </head>

    <body>
        <h1>Привет!</h1>

        <p>Это моя первая HTML-страница.</p>
    </body>
</html>

Это уже настоящий HTML-документ.

И очень важно понять его структуру:

<!DOCTYPE html>
        ↓
говорим браузеру: это HTML-документ

<html>
   ↓
весь документ

   <head>
      ↓
   служебная информация

   <body>
      ↓
   содержимое страницы

Цель занятия

К концу дня ты должен понимать:

как создавать заголовки разных уровней;
как работать с абзацами и переносами;

как создавать ссылки;
как добавлять изображения;
как писать комментарии;
как самостоятельно собрать небольшую информационную страницу.

Сегодня пока не трогаем CSS. Сначала научимся правильно размечать содержимое.

1. Заголовки h1–h6

Вчера мы уже познакомились с h1, но сегодня разберём систему полностью.

HTML предоставляет шесть уровней заголовков:

<h1>Главный заголовок</h1>
<h2>Раздел</h2>
<h3>Подраздел</h3>
<h4>Подраздел 4 уровня</h4>
<h5>Подраздел 5 уровня</h5>
<h6>Подраздел 6 уровня</h6>

Условная структура статьи:

h1 — HTML и CSS
│
├── h2 — Что такое HTML
│   ├── h3 — Теги
│   └── h3 — Элементы
│
├── h2 — Что такое CSS
│   └── h3 — Стили
│
└── h2 — Практика

То есть заголовки создают иерархию документа.

Важный момент

Не стоит выбирать h2, потому что он «выглядит красивее», а h4, потому что он «поменьше».

Заголовок выбирается по уровню смысла, а не по размеру.

Размер потом можно изменить через CSS.

2. Абзацы <p>

Мы уже видели:

<p>Это абзац текста.</p>

Если написать:

<p>Первый абзац.</p>
<p>Второй абзац.</p>

браузер воспринимает их как два отдельных абзаца.

Это отличается от простого переноса строки в исходном коде.

Например:

<p>
    Это один абзац,
    несмотря на переносы
    в коде.
</p>

Для HTML это всё ещё один абзац.

3. Перенос строки <br>

А что, если нам действительно нужен перенос строки внутри одного абзаца?

Используется:

<br>

Например:

<p>
    Первая строка<br>
    Вторая строка<br>
    Третья строка
</p>

На странице:

Первая строка
Вторая строка
Третья строка

br — break, то есть перенос строки.

Важное отличие
<p>Первый текст</p>
<p>Второй текст</p>

→ два абзаца.

<p>Первый текст<br>Второй текст</p>

→ один абзац, но с переносом.

Не нужно использовать <br> для создания больших отступов между блоками. Для этого позже будет CSS.

4. Горизонтальная линия <hr>

Элемент:

<hr>

создаёт тематическое разделение содержимого.

Например:

<h1>Моя статья</h1>

<p>Введение в тему.</p>

<hr>

<h2>Основная часть</h2>

Условно:

Моя статья

Введение в тему.

──────────────

Основная часть

hr — horizontal rule.

Важно: это не просто «линия для красоты». Семантически она обозначает тематический переход между частями документа.

5. Что такое атрибут?

Вот теперь важная новая концепция.

До этого мы писали:

<p>Привет!</p>

Но HTML-элементам часто нужно передавать дополнительную информацию.

Например:

«Это ссылка, которая ведёт на такой-то адрес».

Для этого используются атрибуты.

Пример:

<a href="https://example.com">Перейти на сайт</a>

Разберём:

<a
 ↓
тег

href="https://example.com"
 ↓
атрибут

Перейти на сайт
 ↓
содержимое

</a>
 ↓
закрывающий тег

Атрибут — это дополнительная характеристика элемента.

Общий синтаксис:

<tag attribute="value">Содержимое</tag>

Например:

<p class="text">Привет</p>

Здесь:

p — тег;
class — атрибут;
"text" — значение атрибута;
Привет — содержимое.

Пока class подробно не изучаем — просто знакомимся с принципом.

6. Ссылки <a>

Ссылка создаётся через:

<a href="https://google.com">Google</a>

a — anchor, то есть якорь.

На странице пользователь увидит:

Google

При нажатии браузер перейдёт по адресу из href.

Разбор
<a href="https://google.com">Google</a>
a
├── href → куда перейти
└── Google → текст ссылки

href — один из самых важных атрибутов HTML.

Ссылка на другой сайт
<a href="https://example.com">Открыть сайт</a>
Ссылка на другую страницу своего проекта
<a href="about.html">О нас</a>

Здесь about.html — путь к файлу.

Пока просто запомни: href указывает адрес назначения.

7. Изображения <img>

Для изображения используется:

<img src="cat.jpg" alt="Кот">

Здесь уже интересный момент.

img — пустой элемент. У него нет обычного закрывающего тега:

<img>

а не:

<img></img>

Разберём атрибуты:

<img src="cat.jpg" alt="Кот">
src
src="cat.jpg"

Указывает, где находится изображение.

src = source.

alt
alt="Кот"

Альтернативное текстовое описание изображения.

Оно полезно, если:

изображение не загрузилось;
пользователь использует скринридер;
нужно описать содержание картинки.

Пример:

<img src="cat.jpg" alt="Рыжий кот, сидящий на диване">

alt — это не просто «дополнительный текст». Это часть правильной доступной разметки.

8. Пути к файлам

Представим структуру проекта:

project/
│
├── main.html
│
└── images/
    └── cat.jpg

Если main.html находится в корне, а картинка внутри images, то:

<img src="images/cat.jpg" alt="Кот">

Если изображение лежит рядом:

project/
├── main.html
└── cat.jpg

тогда:

<img src="cat.jpg" alt="Кот">

Пока достаточно понимать:

src — путь к ресурсу.

9. Комментарии в HTML

Иногда нужно оставить заметку в коде, но не показывать её пользователю.

Используются:

<!-- Это комментарий -->

Например:

<h1>Мой сайт</h1>

<!-- Здесь будет основной текст -->

<p>Добро пожаловать!</p>

Браузер не отображает комментарий как обычный текст.

Комментарии нужны для:

пояснений;
временных заметок;
разделения больших участков кода.

🌐 День 3 — Списки, вложенность и HTML-дерево

Вчера мы научились создавать отдельные элементы: заголовки, абзацы, ссылки, изображения.

Сегодня сделаем следующий шаг: научимся объединять элементы в структуру.

Главная идея сегодняшнего дня:

HTML — это не просто последовательность тегов. HTML-документ представляет собой дерево вложенных элементов.

1. Зачем вообще нужны списки?

Представь, что нам нужно вывести языки программирования:

Python
JavaScript
C#
HTML
CSS

Можно написать:

<p>Python</p>
<p>JavaScript</p>
<p>C#</p>
<p>HTML</p>
<p>CSS</p>

Это будет работать.

Но мы потеряли важную информацию:

Эти пять элементов являются списком.

HTML позволяет выразить эту структуру непосредственно.

2. Маркированный список — <ul>

Для обычного списка используется:

<ul>
    ...
</ul>

ul означает unordered list — неупорядоченный список.

Например:

<ul>
    <li>Python</li>
    <li>JavaScript</li>
    <li>C#</li>
    <li>HTML</li>
    <li>CSS</li>
</ul>

Браузер обычно покажет:

Python
JavaScript
C#
HTML
CSS
3. Что такое <li>?

Внутри <ul> находятся:

<li>Python</li>

li — list item, то есть элемент списка.

Получается:

<ul>
 ↓
сам список

<li>
 ↓
отдельный пункт списка

Структура:

ul
│
├── li → Python
├── li → JavaScript
├── li → C#
├── li → HTML
└── li → CSS

Очень важно:

<li> обычно используется как элемент списка внутри <ul> или <ol>.

4. Нумерованный список — <ol>

Теперь представим инструкцию:

1. Открыть VS Code
2. Создать HTML-файл
3. Написать код
4. Открыть страницу

Здесь порядок уже имеет значение.

Для этого существует:

<ol>
    <li>Открыть VS Code</li>
    <li>Создать HTML-файл</li>
    <li>Написать код</li>
    <li>Открыть страницу</li>
</ol>

ol = ordered list.

Браузер обычно покажет:

Открыть VS Code
Создать HTML-файл
Написать код
Открыть страницу
5. ul или ol?

Очень простое правило.

<ul>

Используем, когда порядок не важен:

<ul>
    <li>Python</li>
    <li>C#</li>
    <li>JavaScript</li>
</ul>

Не имеет значения, какой язык стоит первым.

<ol>

Используем, когда порядок имеет значение:

<ol>
    <li>Запустить программу</li>
    <li>Ввести данные</li>
    <li>Получить результат</li>
</ol>

Здесь порядок действий важен.

6. Вложенность

А теперь самое интересное.

Мы можем помещать один элемент HTML внутрь другого.

Например:

<ul>
    <li>Python</li>
    <li>JavaScript</li>
</ul>

Получается:

ul
│
├── li
│
└── li

li является дочерним элементом ul.

А ul является родительским элементом li.

Это очень важные термины:

родитель
   ↓
  ul
   ↓
ребёнок
  li
7. HTML как дерево 🌳

Посмотри на документ:

<html>
    <head>
        <title>My site</title>
    </head>

    <body>
        <h1>My site</h1>

        <p>Hello!</p>

        <ul>
            <li>Python</li>
            <li>JavaScript</li>
            <li>C#</li>
        </ul>
    </body>
</html>

Его можно представить так:

html
│
├── head
│   └── title
│
└── body
    │
    ├── h1
    │
    ├── p
    │
    └── ul
        │
        ├── li
        ├── li
        └── li

Вот почему мы говорим, что HTML имеет древовидную структуру.

8. Вложенные списки

А теперь представим:

Языки
├── Python
│   ├── Django
│   └── Flask
├── JavaScript
│   ├── React
│   └── Vue
└── C#
    └── .NET

Такое тоже можно сделать в HTML.

<ul>
    <li>
        Python

        <ul>
            <li>Django</li>
            <li>Flask</li>
        </ul>
    </li>

    <li>
        JavaScript

        <ul>
            <li>React</li>
            <li>Vue</li>
        </ul>
    </li>

    <li>
        C#

        <ul>
            <li>.NET</li>
        </ul>
    </li>
</ul>

Здесь особенно важно посмотреть на структуру.

Например:

li → Python
│
└── ul
    ├── li → Django
    └── li → Flask

То есть второй список находится внутри конкретного пункта первого списка.

9. Почему вложенность так важна?

Потому что HTML постоянно работает именно так.

Например:

<body>
    <section>
        <h2>Моя статья</h2>

        <p>Текст статьи.</p>
    </section>
</body>

Можно представить:

body
└── section
    ├── h2
    └── p

И позже, когда мы начнём CSS, ты сможешь сказать:

«Сделай только p, который находится внутри section».

Именно поэтому понимание вложенности сейчас будет очень полезно.

10. Родитель, ребёнок и сосед

Рассмотрим:

<ul>
    <li>Python</li>
    <li>JavaScript</li>
    <li>C#</li>
</ul>

Здесь:

ul
│
├── li Python
├── li JavaScript
└── li C#

ul — родитель всех трёх li.

Каждый li — ребёнок ul.

А li Python и li JavaScript являются соседями.

То есть:

        ul
       /  \
      /    \
    li      li
     ↑      ↑
   соседи между собой

Эти понятия нам очень пригодятся в CSS.

📚 День 4 — Работа с текстом в HTML
🎯 Цель дня

Сегодня научиться не просто выводить текст на страницу, а размечать его по смыслу.

После сегодняшнего занятия ты должен понимать:

чем <strong> отличается от <b>;
чем <em> отличается от <i>;
для чего нужен <mark>;
когда использовать <small>;
как оформлять цитаты;
что делает <code>;
почему HTML-теги должны описывать смысл, а не просто внешний вид.
1. <strong> — важность

Начнём с:

<strong>Важно!</strong>

Обычно браузер отображает это жирным:

Важно!

Но главное здесь не жирность.

strong означает:

Этот текст имеет повышенную важность.

Например:

<p>
    <strong>Не удаляйте этот файл.</strong>
</p>

Здесь мы не просто хотим сделать текст жирным.

Мы сообщаем структуру документа:

этот фрагмент текста особенно важен.

2. <b> — просто визуальное выделение

Есть ещё:

<b>Python</b>

Обычно браузер тоже покажет его жирным.

Но смысл другой.

b не сообщает:

«это очень важная информация».

Он скорее говорит:

«выдели этот фрагмент визуально».

Поэтому в семантическом HTML часто предпочтительнее:

<strong>Внимание!</strong>

если текст действительно важен.

Главное:
<strong> → важность
<b>      → визуальное выделение

На экране они могут выглядеть одинаково, но смысл HTML-разметки различается.

3. <em> — смысловой акцент

Теперь:

<em>очень</em>

Обычно браузер отображает его курсивом.

Например:

<p>
    Это <em>очень</em> важно.
</p>

em означает emphasis — смысловой акцент.

То есть мы как бы говорим:

Сделай акцент именно на этом слове.

<i> — опять же, не совсем то же самое

Можно написать:

<i>Python</i>

Обычно это тоже будет курсив.

Но:

<em> → смысловой акцент
<i>  → визуально/типографически выделенный текст

Например, название термина, иностранное слово или особый тип текста может быть выделен через i, если это не смысловой акцент.

Пока главное запомнить:

<strong>Важно</strong>
<em>Акцент</em>
4. <mark> — выделение маркером

Если нужно показать, что какой-то фрагмент выделен/найден/релевантен, существует:

<mark>важный фрагмент</mark>

Например:

<p>
    Изучаем <mark>HTML</mark> сегодня.
</p>

Браузер обычно покажет это как текст с подсветкой.

Очень легко представить mark как настоящий текстовый маркер.

5. <small> — второстепенная информация

Например:

<p>Цена: 100 €</p>
<small>Цена указана без доставки.</small>

small предназначен для второстепенной информации, например:

уточнений;
примечаний;
юридической информации;
копирайта;
небольших пояснений.

Важно:

small не означает:

«сделай любой текст маленьким».

Его задача тоже связана со смыслом.

🧠 Пока остановимся

У нас уже есть:

<strong> → важность
<em>     → смысловой акцент
<mark>   → выделенный/релевантный фрагмент
<small>  → второстепенная информация

Обрати внимание на общую закономерность.

Мы опять занимаемся не:

«Как сделать текст жирным?»

а:

«Что означает этот текст?»

Это одна из главных идей семантического HTML.

6. Цитаты

Теперь представим статью.

Мы хотим привести слова какого-то источника.

Для небольшой цитаты внутри предложения существует:

<q>...</q>

Например:

<p>
    Он сказал: <q>HTML — это структура страницы.</q>
</p>

Браузер обычно сам добавит кавычки.

Большая цитата — <blockquote>

Если цитата занимает отдельный блок:

<blockquote>
    HTML определяет структуру веб-страницы.
</blockquote>

Это уже самостоятельный блок цитаты.

Например:

<h2>Цитата</h2>

<blockquote>
    Хороший HTML описывает смысл содержимого,
    а не только его внешний вид.
</blockquote>
7. <code> — программный код

А вот это особенно пригодится тебе.

Если мы хотим показать HTML-код внутри текста:

<p>
    Используй тег <code>&lt;p&gt;</code> для абзаца.
</p>

Здесь:

<code>...</code>

означает:

Это программный код / фрагмент кода.

Например:

<p>Используй <code>print()</code> в Python.</p>

Или:

<p>
    HTML-элемент начинается с <code>&lt;tag&gt;</code>.
</p>
Почему здесь &lt;?

Потому что HTML воспринимает:

<tag>

как настоящий HTML-тег.

Если мы хотим показать символ < как обычный текст, используем специальную запись:

&lt;

А:

&gt;

означает:

>

Поэтому:

<code>&lt;p&gt;</code>

на странице покажет:

<p>

Пока не нужно запоминать все специальные символы — нам достаточно этих двух.

🧱 День 5 — Контейнеры, вложенность и блочные/строчные элементы









Цель урока
Научиться объединять элементы в группы, понимать разницу между div и span, а также разобраться, почему одни элементы занимают целую строку, а другие располагаются рядом с текстом.



Сегодня будет не только теория: ты увидишь, зачем нужны контейнеры, и попробуешь применить их в своей HTML-странице.

1. Зачем нужны контейнеры?
Представь, что ты создаёшь страницу своего профиля.
На ней есть:
- имя;
- описание;
- список навыков;
- ссылки на проекты.
Можно просто написать все элементы подряд:
<h1>Мой профиль</h1>
<p>Я изучаю программирование.</p>
<h2>Мои навыки</h2>
<ul>
    <li>Python</li>
    <li>HTML</li>
    <li>CSS</li>
</ul>


Это вполне рабочий HTML. Но что, если мы захотим объединить имя и описание в одну группу, а навыки — в другую?
Для этого существуют контейнеры.
Контейнер позволяет сгруппировать элементы, чтобы обозначить их общую структуру, а позднее — например, задать группе стили с помощью CSS.
2. Тег <div> — универсальный контейнер
div — это блочный контейнер общего назначения. Сам по себе он не сообщает, что именно означает его содержимое.
Пример:
<div>
    <h1>Мой профиль</h1>
    <p>Я изучаю программирование.</p>
</div>

<div>
    <h2>Мои навыки</h2>
    <ul>
        <li>Python</li>
        <li>HTML</li>
        <li>CSS</li>
    </ul>
</div>


Теперь у нас две группы:
body
├── div
│   ├── h1
│   └── p
└── div
    ├── h2
    └── ul
        ├── li
        ├── li
        └── li


Обрати внимание: <div> не заменяет заголовки, абзацы или списки. Он объединяет их в группу, сохраняя вложенность.
Когда использовать div?
Например, когда:
- нужно объединить несколько элементов;
- нужно будет стилизовать группу элементов через CSS;
- подходящего семантического элемента пока нет.
Но не стоит оборачивать каждый элемент в div без необходимости. Контейнер должен помогать структуре, а не усложнять её.

3. Тег <span> — строчный контейнер
Теперь представим предложение:
<p>Я изучаю HTML и CSS.</p>


Мы хотим выделить только слово HTML, чтобы позже покрасить его в другой цвет через CSS.
Можно написать:
<p>
    Я изучаю <span>HTML</span> и CSS.
</p>


span — это строчный контейнер общего назначения. Он позволяет выделить часть содержимого внутри строки, не создавая отдельный блочный элемент.
Сравни:
<p>Я изучаю <span>HTML</span> и CSS.</p>


Весь текст остаётся в одном абзаце.
А если написать:
<p>Я изучаю HTML</p>
<p>и CSS.</p>


получатся уже два отдельных абзаца.
Главное различие
<div>  → группирует содержимое в блочном контейнере
<span> → выделяет фрагмент внутри строки


Пока мы не подключали CSS, поэтому span может казаться бесполезным. Но позднее он пригодится, когда потребуется оформить только часть текста.

4. Блочные элементы
Блочные элементы в обычном потоке документа обычно начинаются с новой строки и занимают доступную ширину родительского контейнера.
Примеры:
- <div>
- <p>
- <h1>
- <ul>
- <blockquote>
Посмотрим:
<h1>Мой сайт</h1>
<p>Первый абзац.</p>
<p>Второй абзац.</p>


В обычном отображении они располагаются друг под другом.
Мой сайт
Заголовок — отдельный блок

Первый абзац.
Второй абзац.
Упрощённая иллюстрация блочного расположения.
Важная оговорка: это поведение по умолчанию. Позже CSS позволит менять способ отображения элементов, например с помощью display: flex.

5. Строчные элементы
Строчные элементы обычно располагаются внутри текущей строки и занимают столько места, сколько требуется их содержимому.
Примеры:
- <span>
- <strong>
- <em>
- <a>
- <code>
Например:
<p>
    Я изучаю <strong>HTML</strong>,
    <em>CSS</em> и
    <a href="https://example.com">веб-разработку</a>.
</p>


Все три элемента встроены в один абзац. Они не создают каждый отдельный абзац.
Я изучаю HTML, CSS и веб-разработку.
Упрощённая иллюстрация строчных элементов внутри предложения.
Проверь себя
Какой вариант лучше подходит, если мы хотим выделить только слово Python внутри предложения?
<p>Мой любимый язык — <span>Python</span>.</p>


или
<div>Python</div>


В первом случае мы выделяем часть строки. Во втором создаём отдельный блочный контейнер.

6. Вложенность: кто внутри кого?
Ты уже умеешь строить HTML-дерево. Теперь добавим к нему контейнеры.
Посмотри:
<div>
    <h2>Мои навыки</h2>

    <p>Я изучаю веб-разработку.</p>

    <ul>
        <li>HTML</li>
        <li>CSS</li>
    </ul>
</div>


Дерево:
div
├── h2
├── p
└── ul
    ├── li
    └── li


Здесь:
- div — родитель для h2, p и ul;
- ul — родитель для двух li;
- сами li — соседи;
- li не являются непосредственными детьми div: между ними находится ul.
Это важно не только для HTML. В дальнейшем CSS сможет выбирать элементы по их отношениям друг с другом.

7. Важное правило: div и span не заменяют семантические теги
Допустим, ты создаёшь верхнюю часть сайта.
Можно написать:
<div>
    <h1>Мой сайт</h1>
    <p>Добро пожаловать!</p>
</div>


Это допустимая группировка. Но если мы строим настоящую структуру сайта, позже мы познакомимся с тегами вроде header, main и footer, которые лучше описывают назначение частей страницы.
Аналогично, если текст важен, используй strong, а если это ссылка — a, а не span просто потому, что его удобно стилизовать.
Правило сенсея: сначала выбираем тег по смыслу, а универсальный контейнер используем, когда он действительно нужен.

День 6. Семантический HTML

🎯 Цель урока

1. Что такое семантический HTML?
Вспомним прошлый урок.
<div>
    <h1>Мой блог</h1>
    <p>Добро пожаловать!</p>
</div>


Код корректный, но у браузера нет специальной информации о том, что этот div представляет собой шапку сайта. Это просто универсальный контейнер.

А теперь посмотрим на другой вариант:
<header>
    <h1>Мой блог</h1>
    <p>Добро пожаловать!</p>
</header>


header прямо обозначает смысл блока: это вводная часть страницы или отдельного раздела.

Семантические HTML-элементы — это элементы, которые сообщают смысл и назначение своего содержимого. Они помогают браузерам, поисковым системам и вспомогательным технологиям лучше понимать структуру документа.

Запомните: семантика отвечает на вопрос «Что это за часть страницы?», а не «Как она выглядит?». Внешний вид будем изучать в CSS.
2. Семь важных семантических тегов
header

Вводная часть — шапка

Может содержать заголовок, логотип, краткое описание или навигацию. header бывает не только у всей страницы, но и внутри статьи или раздела.
<header>
    <h1>Мой блог</h1>
    <p>Заметки о программировании</p>
</header>





nav

Основная навигация

Группа важных ссылок, помогающих перемещаться по сайту или его разделам. Не каждую отдельную ссылку нужно помещать в nav.
<nav>
    <a href="/">Главная</a>
    <a href="/articles.html">Статьи</a>
    <a href="/contacts.html">Контакты</a>
</nav>





main

Основное содержимое

Главная по смыслу часть конкретной страницы. Обычно на странице должен быть один видимый main.
<main>
    <h1>Мои статьи</h1>
    <p>Здесь собраны мои публикации.</p>
</main>





section

Тематический раздел

Группирует содержимое, относящееся к одной теме. Обычно у section есть заголовок.
<section>
    <h2>Мои навыки</h2>
    <p>Изучаю HTML и CSS.</p>
</section>





article

Самостоятельная публикация

Подходит для статьи, записи блога, новости или сообщения на форуме — материала, который имеет самостоятельный смысл.
<article>
    <h2>Что такое HTML?</h2>
    <p>HTML задаёт структуру веб-страницы.</p>
</article>





aside

Дополнительная информация

Содержимое, связанное с основной темой, но не являющееся её центральной частью: например, блок «Читайте также» или справочная заметка.
<aside>
    <h2>Читайте также</h2>
    <a href="/css.html">Введение в CSS</a>
</aside>





footer

Заключительная часть

Может содержать сведения об авторе, дату публикации, копирайт или ссылки на дополнительные материалы. Как и header, может находиться внутри статьи или раздела.
<footer>
    <p>Автор: Алексей</p>
</footer>





3. Разница между section, article и div
Это одна из самых важных частей сегодняшнего урока.
div — универсальная группа
Используйте, когда нужно объединить элементы, но у группы нет особого самостоятельного смысла.

section — раздел по теме
Используйте, когда элементы образуют отдельную тематическую часть страницы, например «Обо мне», «Навыки» или «Отзывы».

article — самостоятельный материал
Используйте, когда содержимое можно понять как отдельную публикацию: новость, пост или статью.

Представим страницу блога:
<main>
    <section>
        <h2>Последние статьи</h2>

        <article>
            <h3>Изучаем HTML</h3>
            <p>Моя первая статья об HTML.</p>
        </article>

        <article>
            <h3>Изучаем CSS</h3>
            <p>Моя первая статья о CSS.</p>
        </article>
    </section>
</main>


Здесь:
- main — основное содержимое страницы.
- section — тематический раздел «Последние статьи».
- Каждый article — отдельная публикация.
- h2 — заголовок раздела, h3 — заголовок отдельной статьи.
Важный нюанс: section не обязан содержать article, а article не обязан находиться внутри section. Выбирайте элементы по смыслу, а не по строгому шаблону.

День 7. HTML-таблицы
Этап 1 · Основы HTML · Теория и практика



🎯 Цель урока
Сегодня вы научитесь создавать таблицы, задавать строки и ячейки, выделять заголовки столбцов и объединять ячейки. В конце соберём небольшое расписание занятий.
1. Из чего состоит HTML-таблица?
Для начала познакомимся с четырьмя основными тегами.
table

Вся таблица

Контейнер, внутри которого располагаются строки и другие элементы таблицы.



tr

Строка таблицы

От английского table row. Содержит ячейки одной строки.



td

Обычная ячейка

От английского table data. Содержит данные: имя, число, название предмета и так далее.



th

Заголовочная ячейка

От английского table header. Обозначает заголовок строки или столбца.



Посмотрим на простой пример:
<table>
    <tr>
        <th>Имя</th>
        <th>Возраст</th>
    </tr>
    <tr>
        <td>Алексей</td>
        <td>25</td>
    </tr>
    <tr>
        <td>Мария</td>
        <td>22</td>
    </tr>
</table>


Логически таблица выглядит так:
Имя


Возраст


Алексей

25

Мария

22


Схематическое представление таблицы из примера.

Разберём структуру:
- Первый tr содержит два заголовка: Имя и Возраст.
- Второй tr содержит данные Алексея.
- Третий tr содержит данные Марии.
- Каждый tr объединяет ячейки одной строки.
Запомните: tr создаёт строку, а td и th — ячейки внутри этой строки.
2. Как правильно выбирать th и td?
Рассмотрим расписание:
<table>
    <tr>
        <th>День</th>
        <th>Предмет</th>
    </tr>
    <tr>
        <td>Понедельник</td>
        <td>HTML</td>
    </tr>
    <tr>
        <td>Вторник</td>
        <td>CSS</td>
    </tr>
</table>


Здесь День и Предмет — заголовки столбцов, поэтому мы используем th. Названия дней и предметов — данные, поэтому они помещаются в td.

У th есть важное преимущество: он обозначает ячейку как заголовок для связанных с ней данных. Для более доступных таблиц можно явно указывать назначение заголовка с помощью атрибута scope:
<th scope="col">Предмет</th>
<th scope="row">Понедельник</th>


- scope="col" — заголовок столбца.
- scope="row" — заголовок строки.
Пока достаточно понимать, зачем это нужно. В практическом задании мы начнём с обычных th и td.
3. Группы строк: thead, tbody и tfoot
У таблицы могут быть три дополнительные смысловые части:
- thead — группа строк с заголовками таблицы.
- tbody — основное содержимое таблицы.
- tfoot — итоговая или заключительная часть, например строка с суммой.
Пример таблицы расходов:
<table>
    <thead>
        <tr>
            <th>Покупка</th>
            <th>Цена</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <td>Книга</td>
            <td>300 Kč</td>
        </tr>
        <tr>
            <td>Тетрадь</td>
            <td>50 Kč</td>
        </tr>
    </tbody>

    <tfoot>
        <tr>
            <th scope="row">Итого</th>
            <td>350 Kč</td>
        </tr>
    </tfoot>
</table>


Эти элементы помогают логически разделить таблицу. Они не заменяют tr, th или td, а группируют строки. Браузер может отображать такую таблицу без специальных стилей, но оформление мы изучим позже в CSS.
4. Объединение ячеек: colspan и rowspan
Иногда одна ячейка должна занимать несколько столбцов или строк.
colspan — объединение по горизонтали
<table>
    <tr>
        <th colspan="2">Моё расписание</th>
    </tr>
    <tr>
        <td>Понедельник</td>
        <td>HTML</td>
    </tr>
</table>


colspan="2" означает, что заголовочная ячейка занимает пространство двух столбцов.
rowspan — объединение по вертикали
<table>
    <tr>
        <th rowspan="2">Понедельник</th>
        <td>HTML</td>
    </tr>
    <tr>
        <td>Практика</td>
    </tr>
</table>


rowspan="2" означает, что ячейка Понедельник занимает две строки.

Второй строке не требуется ещё одна ячейка для дня недели: она уже покрыта объединённой ячейкой.
